# UI guide

Applies to every screen. Behaviour is in `SPEC.md`. Where this file and a generated design system disagree, **this file wins**.

## Principles
- Mobile first: design at 360 px, then widen. Most members use a phone.
- Clean, Vercel/Linear-like: cards, clear type, generous spacing, one accent colour.
- Indonesian copy, friendly but polite. Short sentences.
- The question and the answer form are the product. Everything else stays quiet.

## Design system
- Components: shadcn/ui on Tailwind. Do not add another component library.
- A starting design system is generated by the UI/UX Pro Max skill at `design-system/mathletics-daily/MASTER.md`. Use it for spacing, type and component ideas, but:
  - **One accent colour only: deep navy `#0B1F4D`** (the client's colour theme). The generated file proposes cyan plus a green CTA; ignore that. Use green and red only for correct/incorrect status, and check they reach 4.5:1 in both modes.
  - **Contrast is checked.** Navy on white is about 15.9:1. Navy cannot be text on a dark background, so in dark mode the navy becomes the surface and the accent switches to a lighter tint of the same hue (see the palette below).
  - Dark mode is required (follows the system, plus a toggle), even if the generated file avoids it.
  - Page-specific overrides go in `design-system/mathletics-daily/pages/<page>.md`.
- Define colours as CSS variables in `app/globals.css` and use them through Tailwind tokens. No hard-coded hex in components.

## Brand palette (starting values)
Define these as CSS variables in `app/globals.css`, mapped onto the shadcn tokens (`--background`, `--foreground`, `--card`, `--muted-foreground`, `--primary`, `--primary-foreground`).

| Token | Light | Dark |
| --- | --- | --- |
| background | `#FFFFFF` | `#060F29` |
| card / surface | `#F5F7FC` | `#0B1F4D` |
| foreground | `#0B1F4D` | `#F1F5FF` |
| muted text | `#5B6B8C` | `#A9B6D6` |
| primary (buttons, links) | `#0B1F4D` | `#9DB4FF` |
| primary-foreground | `#FFFFFF` | `#0B1F4D` |

Contrast, computed (WCAG): light foreground on background 15.9:1, muted text on white 5.4:1. Dark foreground on background 17.4:1, on card 14.6:1, muted on background 9.3:1, primary on background 9.4:1, primary-foreground on primary 7.9:1. Re-check with a contrast tool if you change any value.

## States (every screen)
Loading (skeleton), empty (friendly text and a next step), error (toast and an inline message), success (toast "Jawaban terkirim").

## Math rendering
- KaTeX via `react-markdown` + `remark-math` + `rehype-katex`; import `katex/dist/katex.min.css` once in the root layout.
- Long formulas scroll horizontally inside their block; never break the page layout on a phone.
- Question text should be at least 16 px on mobile.

## Key screens
- **Today's question:** question first, countdown in a quiet badge, answer form below. Final answer field, then steps (photo button first, text optional), then Kirim. Confirmation dialog before the first submit.
- **Photo upload:** camera or gallery picker, thumbnails with a remove button, per-photo progress, compress before upload.
- **Leaderboard:** compact rows, own row highlighted and sticky, tabs for Keseluruhan and Minggu Ini.
- **Grading:** one screen, no page changes. Left: final answer, auto-verdict, steps, photo viewer (zoom, rotate). Right: mark-scheme checkboxes, feedback, total preview, Simpan. Keyboard shortcuts visible as hints.

## Accessibility checklist
- [ ] Text contrast at least 4.5:1 (large text 3:1) in light and dark
- [ ] Visible focus ring on every interactive element
- [ ] Tap targets at least 44 px
- [ ] Form fields have labels; errors are announced and tied to their field
- [ ] Images (diagrams) have alt text; icons have labels
- [ ] Respects `prefers-reduced-motion`
